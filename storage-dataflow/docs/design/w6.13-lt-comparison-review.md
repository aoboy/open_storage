# W6.13 — LT Comparison-Window Review

**Date:** 2026-11-20
**Scope:** the opt-in Rust LT arm versus the C LT arm. Nanorq remains C and is
outside this review; this document is not a default-change authorization.
**Decision:** [ADR-0010](../adr/0010-retain-c-default-for-lt.md) retains C as
the default and keeps Rust LT opt-in.

## Evidence available

| Area | Evidence | Status |
|---|---|---|
| Public surface | W6.8 cbindgen check: 15 functions, 5 typedefs, 2 structs, 1 enum identical | Historical only (`77e0292`, `568c30c`, `180f025`) |
| C/Rust tests | W6.8: C and Rust each passed the then-current 23 CTest entries | Historical only |
| Deterministic parity | W6.8: 556 comparisons byte-identical in both variants; current C tree: 1,410 comparisons, zero pending | Current Rust parity not executed |
| Both-variant consumers | W6.8 installed pkg-config, `find_package`, CFFI, and Debian consumers ran both arms | Current wheel leg ran the C variant only |
| Hosted correctness | None | W6.11 runner absent |
| Paired performance | None; W6.12 has single-runner C records only | Rust samples absent |
| Nightly history | None | No runner; zero paired samples |

The W6.8 figures are truthful for that revision but predate the current tree.
Since then the suite grew to 26 C tests and the parity corpus to 1,410
comparisons, including new LT K=1/T=256 and K=64/T=1 geometries and fail-closed
codec-selection checks. `cargo` is unavailable here, so neither the current
suites nor the new vectors have been run against Rust.

## Cutover-gate evaluation

| ADR-0003/W6.13 criterion | Result |
|---|---|
| Hosted full matrix green at a recorded revision | **Not met** — no runner |
| Current C and Rust suites and parity byte-identical | **Not demonstrated** — Rust not run on current tree |
| Seven paired same-runner nightly samples | **Not met** — zero samples |
| No workload regression beyond the 5% noise rule | **Not evaluable** — no paired samples |
| Both-variant installed consumers | **Historical only**; current tree verified for C |
| Rollback plan | Defined in ADR-0010; not exercised because no switch occurs |

Missing evidence is recorded as missing, not as a performance result. Local
C-only measurements cannot substitute for paired same-runner data.

## Decision

Per W6.13's status-quo branch:

1. C remains the default LT arm.
2. Rust LT remains selectable with `SDF_USE_RUST_FOUNTAIN=ON`.
3. No C LT code is removed; no public ABI, golden vector, or package name
   changes.
4. The comparison window stays open. W6.13 is revisited when W6.11 and W6.12
   supply the evidence listed above.

## Reproduction and skips

Current local gate, executed for the C default:

```sh
cd storage-dataflow
make ci
```

Result: lint/ruff/mypy clean; 26/26 CTest in default, ASan+UBSan, and TSan;
68/68 Python; install, Debian, and wheel legs green. `scripts/test_rust_seam.sh`
and `scripts/test_rust_fountain.sh` report `cargo` absent and skip; the hosted
matrix and nightly history are not run. These skips are the reason for the
retention decision, not a negative verdict on the Rust arm.

## Limits

- No hosted, production-network, or cross-machine performance claim is made.
- No claim is made that Rust is faster, slower, or equivalent on the current
  tree; that measurement does not exist here.
- A future default change requires the separate reviewed landing described in
  ADR-0010.
