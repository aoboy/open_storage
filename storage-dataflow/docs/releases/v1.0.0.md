# v1.0.0 — storage-dataflow beachhead release

**Release date:** 2026-11-19  
**Tag:** `v1.0.0`  
**Version source:** `include/sdf/version.h` (C ABI, pkg-config and CMake
config); the Rust seam crate and Python control-plane package are aligned
at 1.0.0.

plane and the CFFI bindings implemented across W0–W6.6. These notes are
compiled from the evidence ledger in
[08-implementation-plan](../design/08-implementation-plan.md); commit
hashes and command output below are the completion record.

## What is in the release

### W0 — foundations

- SPSC ring, seqlock, pool, timer, shared memory, metrics, logging and
  strict TOML configuration (`f53c872`, `cf361ab`, `2a17946`, `c0dd25f`,
  `d40f066` and follow-ups).
- Golden-vector extraction rather than re-derived expectations; the
  parity harness is an executable gate, not a documentation claim
  (`d20f5a8`, `d106332`).
- Benchmarking, sanitizer and CI gate shape follows wack_a_mole
  (`394c597`, `d9b3c6e`, `ad0cf6e`, `99fdc31`).

### W1 — origin-driver seam (ADR-0008)

- Stable `sdf_origin_ops_t` ABI with stats and drain/EAGAIN semantics
  (`ce5e63e`).
- Loopback harness and persistent HTTP drivers; loadgen degradation
  profiles for steady, slow, dying and flapping origins (`7ecb66c`,
  `220f58b`, `b6de4aa`, `1428f37`, `5411ff2`, `ffc46fd`).

### W2 — Whack-a-Mole dispatch (P1)

- Seeded dispatch, path LUT/rotation, embodiments with residual cursors
  and last-healthy guard, SHM publication and the Python control loop.
- Seeded-dispatch parity is **280/280 comparisons** inside the 556-total
  gate (`4915b27`, `cf7e6f5`, `6a90d13`).
- Runnable cache-fill proxy and green degradation/bytes-neutral e2e legs
  (`f398a09`, `35a73e7`, `def1e48`, `70bb9ed`, `b613f69`).
- Cross-language SHM proven live, including the CFFI header-graph and
  origin-link correction (`d4b7b94`, `750f2b2`, `c1b0bf7`).

### W3 + W6.3 — fountain codecs and FLUID repair (P2)

- One opaque codec ABI with explicit ESI, lifecycle and rank semantics;
  vendored RaptorQ (nanorq) plus the in-repo systematic LT arm
  (`ec3c8ad` and the W3 ledger entries).
- FLUID sender budget and cumulative-loss-product gate, with mandatory
  ARQ fallback rather than shipping incomplete blocks.
- **N-block objects** (up to 64): per-block codec/budget/gate,
  decode-deficit-ranked admission, per-block fallback and round
  accounting (`ac9332c`, `3104fd2`).
- Decode success is now **byte-exact**: each reconstructed block is
  compared with its deterministic sender block. This exposed the old
  LT test's Nanorq-encoded fixture, which previously passed on garbage;
  the fixture is now arm-specific (`3104fd2`).

### W4 + W6.4 — ARC pacing (P3)

- Paper Algorithm 1/2/3 behavior: asymmetric D update, quantized E,
  ordered QG release with bounded guard and receiver-only clock.
- Shadow/live/killed sidecar and the deploy controller. W6.4 adds
  `arc_set_mode()` and `arc_sidecar_set_mode()`; a requested flip lands
  on the next pump and killed drains held backlog in that pump
  (`9d56e78`).
- CFFI now covers `origin.h → wm.h → arc.h → fluid.h → fountain.h`, and
  `CffiSidecarTransport` drives the real C sidecar. The extension also
  builds from installed headers/archives (`301e306`).
- One-pump flip/kill-drain C test, two live CFFI controller tests, and
  the kill-switch runbook run through the real transport (`c099e03`).

### W5 — hardening, packaging, Rust seam

- Three stream/vector fuzzers; the ARC fuzz leg found and fixed a real
  QG park-stranding defect.
- Installable headers and static archives with pkg-config and CMake
  package metadata.
- Full declaration-level Rust seam; cbindgen plus a parsed ABI diff
  (`9599843`).

### W6 — production-chain closure

- Live proxy and sidecar scrape endpoints (W6.1; `8942d34..b029aec`).
- Live process-pair chain: C proxy → SHM telemetry → Python loop →
  published profile → acquired profile → scrape (W6.1;
  `67ccd86..b029aec`).
- ARC §12.3 vectors extracted through the public ABI; parity moved to
  556 comparisons with zero pending (W6.2; `ab5ec88`, `e7ed21f`).
- Hosted CI defined as eight jobs plus the nightly p99 regression gate;
  every leg has a local mirror (W6.5; `07a7a18`, `e5141e2`, `cbc5bd9`).
- Multi-block repair and full CFFI/control surface (W6.3/W6.4 above).
- v1.0.0 version alignment and the Debian build/install leg (W6.6;
  `ef737b9`).

## Artifacts

- **Source tag:** `v1.0.0`.
- **Development package:** `libsdf-dev_1.0.0_amd64.deb` on amd64; other
  architectures use the same build script and `dpkg --print-architecture`.
- **Payload:** `/usr/include/sdf`, `libsdf_*.a`, vendored `libnanorq.a`,
  pkg-config files and `find_package(sdf)` CMake config. No shared
  library, maintainer script or runtime dependency is introduced.
- **Build/package commands:**
  `./scripts/build.sh`, `./scripts/build_deb.sh`.
- **Package acceptance:** `./scripts/test_deb.sh` builds the package,
  installs into an isolated rootfs, and compiles/runs
  `tools/install_hello.c` against that payload.

rpm and Helm remain explicitly marked placeholders.

## Known limitations at v1.0.0

1. **Hosted execution evidence:** no first hosted CI run exists because
   the repository has no remote/runner. The matrix is implemented and
   locally mirrored; this is not reported as a hosted green run.
2. **Functional Rust:** the seam declares and checks the complete ABI,
   but no production Rust codec replaces the C implementation yet
   (W6.8).
3. **True ARC shadow scoring (closed after v1.0.0 by W6.10):** at v1.0.0
   shadow still mapped to the IMMEDIATE pacer, so shadow added-latency
   evidence was not yet a non-vacuous production promotion gate. W6.10 now
   runs the non-applying QG schedule and rejects vacuous evidence; see design
   03's true-shadow implementation note. This release note records the state
   at v1.0.0, not the current tree.
4. **S3/NVMe-peer origins:** remain design-note/endpoint gated (W6.7).
5. **HTTP origin:** the reference driver is functional, but remains a
   reference leg rather than a tuned high-performance transport.
